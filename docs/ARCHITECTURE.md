**Key layers:**

- **Domain** — `src/types/game.ts` (now also `Puzzle`, `PuzzleSolution`, `PuzzleBundle`, `PuzzleThemeId`, `DailyPuzzleResult`), `src/constants/game.ts`, `src/constants/levels.ts`, `src/constants/puzzleThemes.ts`. Plain TS types and config tables.
- **Logic** — `src/utils/calculator.ts`, `src/utils/gridGenerator.ts`, `src/utils/rng.ts` (seeded RNG), `src/utils/puzzleBuilder.ts` (used by the build-time generator). Pure, deterministic, no React.
- **Puzzle bundle** — `public/puzzles.json` (450 puzzles, schema v1) generated by `scripts/generate-puzzles.ts` and validated by `scripts/validate-puzzles.ts`. Loaded once on first `/daily` mount via `puzzleStore.loadPuzzleBundle()` and cached for the session.
- **State**
  - `src/store/gameStore.ts` — Zustand. Per-session play state. Three entry actions: `initializeGame(difficulty, mode)` for Play, `initializeLevel(levelId)` for Learn, `initializePuzzle(puzzle)` for Daily.
  - `src/store/progressStore.ts` — Zustand + `persist` to `localStorage` (key `gridgenius:progress:v2`). Long-lived player progress: `levels`, `xp`, learning `streak`, plus `daily` (per-date result) and `dailyStreak`. Updated by `ResultPage` once per game end.
  - `src/store/prefsStore.ts` — Zustand + `persist` (`gridgenius:prefs:v1`). `theme`, `audience`, `zen`. Read by `ThemeApplier`, `SettingsDrawer`, `ButtonGameBoard`, `ResultPage`.
  - `src/utils/puzzleStore.ts` — **utility module**, not a Zustand store. Module-local cache for the bundle, plus pure helpers (`queryPuzzles`, `pickDailyPuzzle`, `utcDateKey`). The `usePuzzles()` React hook in `src/hooks/usePuzzles.ts` wraps the loader.
- **View** — `src/components/`. React + Tailwind + Framer Motion. `src/main.tsx` wraps `<App>` in `<ErrorBoundary>`; `<App>` wraps the router in `<MotionConfig reducedMotion="user">`. Routes flow through a `HomeShell` that owns the Learn / Play tabs and the Settings drawer trigger.

**Routes (current):**

- `/` → `HomeShell` redirects to last-used tab (default `/learn`).
- `/learn` → `LearningPath` (25 nodes from `LEVELS`, gated by `progressStore`) + `DailyPuzzleBanner` at the top.
- `/play` → `GameModeSelector` (lobby).
- `/play/difficulty` → `DifficultySelector` (non-Quick modes only).
- `/game?level=u1-l1` → Learn-mode game via `initializeLevel`.
- `/game` (no `level`) → Play-mode game via `initializeGame`.
- `/daily` → `DailyPuzzlePage` → resolves today's puzzle via `pickDailyPuzzle()`, then `initializePuzzle`.
- (Removed in EPIC-06.07: `/operators`, `OperatorSelector`.)

**Data flow** — Play mode (per round):

```
GameModeSelector → setDifficulty → /game
    └─ ButtonGameBoard mount → useGameStore.initializeGame()
         ├─ generateValidGrid()        (utils)
         ├─ getAllCombinations()       (utils)
         └─ generateTargets()          (utils)
    User taps tile/operator → local component state
    On full selection → submitSolution(tiles, ops)
         └─ calculatePathResult() === currentTarget ?
              ├─ score++; setTimeout 1.5s → nextRound()
              └─ no-op + feedback toast
    Round N === totalRounds → gameStatus = 'completed' → ResultPage (Play view)
```

**Data flow** — Learn mode (per level):

```
LearningPath → tap unlocked node → /game?level=u1-l1
    └─ ButtonGameBoard mount → useGameStore.initializeLevel(levelId)
         ├─ getLevel(levelId)                   (constants/levels)
         ├─ generateValidGridFromConfig()       (utils)
         ├─ getAllCombinationsFromConfig()      (utils)
         └─ generateTargetsFromConfig()         (utils)
    User taps → submitSolution(tiles, ops)
         ├─ correct: score++; setTimeout 1.5s → nextRound()
         └─ wrong:   wrongAttempts++ ; feedback toast
    Round N === totalRounds → gameStatus = 'completed' → ResultPage (Learn view)
                                                          │
                                                          └─ progressStore.completeLevel(id, stars, score)
                                                               ├─ best-of stars + score
                                                               ├─ XP += (newStars - oldStars) * 10
                                                               └─ streak rolls forward (UTC day boundary)
```

**Data flow** — Daily Puzzle (single round, deterministic):

```
DailyPuzzleBanner / direct nav → /daily
    └─ DailyPuzzlePage mount
         ├─ usePuzzles()                        (hooks/usePuzzles)
         │     └─ loadPuzzleBundle()            (utils/puzzleStore — cached after first call)
         │           └─ fetch /bingo/puzzles.json
         └─ pickDailyPuzzle(puzzles, today)     (utils/puzzleStore)
               └─ deterministic by `daily|<utcDateKey>|...` (utils/rng)
    └─ ButtonGameBoard mount with puzzle prop
         └─ useGameStore.initializePuzzle(puzzle)
              └─ writes puzzle.tiles + puzzle.target straight into state
                 (no grid generator runs — what's on disk is what plays)
    User taps → submitSolution(tiles, ops)
         ├─ correct: gameStatus = 'completed' → ResultPage (Daily view)
         └─ wrong:   wrongAttempts++ ; feedback toast
    On Daily ResultPage mount:
         └─ progressStore.completeDailyPuzzle(puzzleId, wrongAttempts, seconds)
              ├─ idempotent per UTC date (repeat solves don't double-count)
              ├─ daily[YYYY-MM-DD] = { puzzleId, wrongAttempts, seconds }
              └─ dailyStreak rolls forward (independent of learning streak)
```

### Progress model (Learn path)

Persistence is intentionally tiny — one Zustand store, JSON-serialised to `localStorage` under `gridgenius:progress:v1`. Schema versioned on the key so a future shape change can migrate cleanly.

```ts
type LevelProgress = {
  completed: boolean;
  bestStars: 0 | 1 | 2 | 3; // best-of, never decreases
  bestScore: number;
  playCount: number;
};

type ProgressState = {
  levels: Record<string, LevelProgress>;
  xp: number; // sum of stars * 10
  streak: { count: number; lastPlayedDate: string | null };
};
```

**Unlock rule.** First level of `LEVELS` is always unlocked. Any subsequent level unlocks when the previous level's `bestStars >= 1`. The rule spans units (e.g. `u2-l1` unlocks when `u1-l5` is completed). Implemented as a pure helper in `progressStore.ts` (`isLevelUnlocked`), so the same logic powers UI gating and tests.

**Stars** (`computeStars(wrongAttempts)`): 3 if `wrongAttempts === 0`, 2 if `<= 1`, else 1. Pure function; tested independently.

**Streak** rolls on UTC date (ISO `YYYY-MM-DD`). Same-day completions don't bump; next-day completions bump by 1; gap > 1 resets to 1. **No** freezes, **no** notifications (vision constraint).

## Target — End of Phase 1 (UX polish) — **shipped in v0.2.0**

Phase 1 closed on 2026-05-10. The bullets below were the plan; outcomes against each are inline.

- **Theme** — ✅ shipped. Tailwind `darkMode: 'class'` + `prefsStore.theme` + `ThemeApplier` component (no full provider needed; the applier is a side-effect-only `useEffect`).
- **Settings store as a separate Zustand slice with `persist`** — ✅ shipped as `prefsStore` (`gridgenius:prefs:v1`). A second long-lived slice, `progressStore`, also persists.
- **`<ErrorBoundary>`** — ✅ shipped at the app root in `main.tsx`.
- **A11y layer** — ✅ partially shipped. Keyboard nav lives directly in `ButtonGameBoard` (roving `tabIndex`, arrow-key handlers, `?` help dialog) rather than in a dedicated `useGridKeyboard` hook — extracting it is a future refactor and isn't blocking. ARIA live regions are in place on `TargetDisplay` and `CalculationFeedback`.
- **Wizard state moves into the store** — ❌ deferred (`EPIC-16.03`). Mode / difficulty selection still lives in `App.tsx` `useState`; refresh on `/game` redirects to `/play` instead of resuming the wizard. Tracked.

## Target — End of Phase 4 (Multiplayer)

Adds real-time. Start on Supabase Realtime; introduce a custom Node service if/when scaling demands.

```
                  ┌──────── Supabase Realtime ────────┐
                  │  channel: game:<uuid>            │
                  │  channel: tv                      │
                  │  channel: lobby                   │
                  └─────────────┬─────────────────────┘
                                │ WebSocket
        ┌───────────────────────┴───────────────────────┐
        ▼                                               ▼
┌──────────────┐                               ┌──────────────┐
│  Player A    │                               │  Player B    │
│  React +     │                               │  React +     │
│  rt-client   │                               │  rt-client   │
└──────────────┘                               └──────────────┘
        │                                               │
        └─────► Edge Function: validate-move ◄──────────┘
                ├─ authoritative grid + target
                ├─ stamps server time
                └─ persists session row + final result

                Spectators subscribe read-only to game:<uuid>
                /tv subscribes to tv channel; rotates featured games
```

**Concurrency model:** server is authoritative for the puzzle and timing; clients render optimistically and reconcile on server ack. No CRDTs needed — single-player puzzle state per side.

**Anti-cheat:** Edge function inspects time-to-solve distribution and flags outliers asynchronously.


## Cross-cutting concerns (all phases)

| **i18n**         | `react-i18next` from Phase 6.                                                                            |
| **Tests**        | Vitest + RTL + Playwright. CI from Phase 0 on.                                                           |
